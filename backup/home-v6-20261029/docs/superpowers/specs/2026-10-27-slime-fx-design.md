## 1. 背景与目标

游戏是单文件手机端网页游戏「最强召唤师系统」：纯 CSS 史莱姆、emoji 图标、localStorage 存档、五个 tab（状态 / 召唤 / 出行 / 空间 / 背包）。

三处明显短板：

1. **打击感几乎为零**。12 属性弹道特效已按元素分化（`doElementBallEffect`，行 3734），但命中结果只写中央一行战报（`performAction`，行 4435）；血条直接改宽度（`refreshBars`，行 4520），受击不闪、不震、不飘字，击杀无演出。
2. **史莱姆长得都一样**。12 属性只有 `--h/--s/--l` 色相差，轮廓一律是同一个圆 blob（`.slime .blob`，行 253）。
3. **战斗里玩家没有决策**。只能选人和调速度，12×12 克制表（行 1025）与 12 套元素天赋（行 1041）对玩家操作没有影响。

本次目标：在不引入任何图片、音频、Canvas 的前提下，补齐这三块。

## 3. 通用地基：FX 模块

### 3.1 结构

在 `startAbyssBattle`（行 3483）之前新增文件级对象 `FX`，约 130 行，对外只有五个方法：

```js
FX.bindField(el)              // 战斗开始时绑定 .battle-field
FX.shake(kind)                // 'light' | 'crit' | 'kill'
FX.flash(el, isCrit)          // 目标 .slime 元素
FX.float(el, text, opt)       // opt: {cls:'crit'|'good'|'weak'|'miss'|'', offsetY}
FX.die(el)                    // 击杀动画 + 爆散
```

### 3.2 约束

- **容器**：沿用 `.battle-field`（行 637 已是 `position:relative; overflow:hidden`），弹道 orb 本来就 append 到这里（行 3700）。飘字与粒子同容器，坐标系由 `FX` 内部用 `fieldEl.getBoundingClientRect()` 与目标元素 rect 计算；现有 `getCoords()`（行 3668）保持不动，继续供弹道使用。
- **时长**：`FX` 内部读全局 `battleSpeed`（行 3487 起有效）。`battleSpeed >= 5` 时飘字时长 ×0.6、同目标合并窗口从 150ms 放宽到 250ms，避免高速档刷屏。
- **性能**：同屏飘字上限 12 个、粒子上限 60 个，超出时丢弃最早的元素。
- **无障碍**：新增全文件唯一一处 `@media (prefers-reduced-motion: reduce)`，只关闭震屏，保留飘字与闪白。
- **存档**：本模块不触碰 `S`，旧存档零迁移。

## 4. A 部分：打击感

### 4.1 命中闪白

目标 `.slime` 加 `.hit-flash` 类 120ms：

- 普通：`.breath` 上 `filter: brightness(2.3) saturate(.35)`
- 暴击：额外 180ms 白色描边（`box-shadow: 0 0 0 2px #fff8`）+ 轻微 `scale(1.06)`

`filter` 加在 `.breath`（行 251）而非 `.slime`，因为 `.slime` 已被外层容器用 `transform: scale(.36)` 缩放（行 655）。

### 4.2 震屏

抖 `.battle-field` 本身，因此只包含星点、两排单位、战报，**不含**顶部 `.game-hud`（速度条与撤退按钮，行 3526/3531）。

| 档位 | 触发 | 位移 | 时长 |
|---|---|---|---|
| light | 普通命中 | ±3px | 120ms |
| crit | 暴击 | ±6px | 160ms |
| kill | 击杀 | ±5px | 140ms |

同一帧内多次震屏只取最强档，不叠加。

### 4.3 伤害飘字

从目标单位顶部生成，上飘 24px，0.85s 淡出。字重 800、`text-shadow` 双层描边保证在暗红背景可读。

| 场景 | 文本示例 | 样式 |
|---|---|---|
| 普通伤害 | `-142` | 白色 13px |
| 暴击 | `-256!` | 金色 `#ffd166`、17px、入场 scale 1.3→1 |
| 属性克制 | `-188 克制` | 橙色，后跟 10px「克制」小标签 |
| 属性微弱 | `-64` | 灰色 11px |
| 治疗 | `+180` | 绿色 `#86efac` |
| 闪避 | `MISS` | 淡紫斜体，向右漂移 |
| 持续伤害 | `-18` | 暗红 11px，图标 🔥/☠ 前缀 |

同目标连续飘字向上错开 14px；合并窗口内的多段伤害累加为一个数字。

### 4.4 击杀演出

`.anim`（行 250，`transform-origin: 50% 100%`）加 `.dying`：0.32s 先 `scale(1.2)` 再 `scale(.15)` 且 `opacity: 0`，`animation-fill-mode: forwards`。同时 `FX.burst` 从单位中心爆出 10–14 颗元素色圆点，复用 `spawnRadiantOrbs` 的径向渐变球样式（行 3690）。战报中已有的「倒下」文案保留。

死亡后 `data-dead="1"` 的平眼状态（行 306 起）保持不变，供战后捕捉界面使用。

### 4.5 血条残影

`.hpbar` 内新增 `<i class="ghost">` 层：白色半透明，宽度 `transition: width .24s ease-out .24s`，由 `refreshBars` 同步写入真实宽度。主条仍是现有渐变（行 672）。

血量 < 30% 时 `.hpbar` 加 `.low`，红色 `pulse` 闪烁。护盾条（行 687）同步残影。

## 5. B 部分：属性形态语言

### 5.1 实现方式

`slimeHTMLFromColor`（行 1469）改两处：

1. `.slime` 元素加属性 `data-el="${opts.element || 'sys'}"`；
2. `.breath` 内、`.fx` 之前插入一个空的 `<div class="mark"></div>`。

装饰全部由 CSS 按 `[data-el="火"] .mark::before` 之类选择器绘制，**不改 DOM 结构、不新增 JS 逻辑**，因此自动继承所有表情、死亡、幽灵、迷你、护盾覆盖状态。

不放在 `.fx` 上，因为 `.fx::before/::after` 已被 sleep（`z` 字符，行 289）和 fear（`〰`，行 300）占用。

### 5.2 坐标与安全检查

- 统一基准 `140 × 118`（`.slime` 尺寸，行 244），外层靠 `transform` 缩放到 1.0 / .43 / .36 / .28 四种尺度，装饰自动跟随。
- 禁入区：眼睛位于 `top: 57%`、跨度约 `x 34–106px`（行 271–272），装饰只允许出现在顶部 `y < 40px`、左右两侧 `x < 30px / x > 110px`、底部 `y > 100px`。
- 与表情冲突检查：`happy` 用右上 `.halo`（行 279），因此「光」的装饰走底部光晕而非顶部光环。

## 6. C 部分：战斗决策

### 6.1 三态开关

存档新增 `S.battleMode`，取值 `'auto' | 'interject' | 'step'`，默认 `'auto'`。`.game-hud` 内新增一个循环切换按钮（自动 / 插话 / 逐回合），切换立即生效并 `save()`。

- `auto`：完全现状，行为与当前版本一致（回归基线）。
- `interject`：自动节奏不暂停；玩家可随时从技能条发起一次手动行动。
- `step`：轮到己方某单位时暂停等待玩家，8s 无操作自动普攻。

### 6.2 主动技

每个元素一个主动技，CD 3 回合，效果全部复用现有机制，不新增战斗机制：

### 6.3 UI

- 技能条：`.battle-field` 底部内侧一行，最多 5 个己方存活单位头像；点头像展开「普攻 + 主动技」两个按钮；再点敌方单位（高亮描边）释放；`step` 模式下当前行动单位默认展开。
- 每个单位每回合最多手动行动 1 次（`u.acted`，`nextTurn` 重置），防止刷技能。
- 手动行动不消耗该单位的自动行动——它是插入，不是替换，除非在 `step` 模式。

### 6.4 调度改造

- `nextTurn`（行 4627）现有 `later()` 链不动；只在 `step` 模式下把每个 actor 的 `performAction` 调用替换为 `waitForPlayer(unit, side)`：置 `B.paused`，渲染技能条，玩家操作或 8s 超时后恢复并继续后续 actor。
- `interject` 模式完全走新分支：玩家点选后直接调用一次 `performAction` 的伤害段，不触碰 `nextTurn` 的计时器。
- 运行时字段 `u.cd{}`、`u.acted` 只在 `initBattleUnit`（行 3545）构造，不写入存档（与状态层 `u.st` 分开，避免被状态叠层逻辑误读）。

### 6.5 存档兼容

只新增 `S.battleMode`。`load()` / `normalizeSlime()` 对缺失字段补 `'auto'`，旧存档无感升级。

## 7. 实施顺序与验收标准

三块一次实现，但按 A → B → C 顺序提交代码，每块有独立通过条件，便于定位回归。

**A 通过条件**
1. 每次命中必同时出现闪白与飘字；暴击为金色且字号更大。
2. 击杀有爆散动画且单位消失，不残留可点击的旧节点。
3. 血条残影可辨（延迟 240ms）。
4. 4.6 表格中 10 个接入点全部分支实测触发。
5. 10x 速度下连战 30 回合，飘字不出现整屏重叠（同目标合并生效）。
6. `prefers-reduced-motion` 下无震屏、无报错。

**B 通过条件**
1. 12 属性在 140px 原始尺度下不看名字可分辨。
2. 8 种表情 × 12 属性抽样组合无遮挡（眼睛区不得被装饰覆盖）。
3. 四种尺度下装饰不溢出容器。
4. 系统史莱姆、`data-dead`、`data-ghost` 外观不劣化。

**C 通过条件**
1. 三态切换生效且刷新后保持。
2. `auto` 模式下 20 回合战斗与改动前逐条战报一致（回归基线）。
3. `interject` 下插入技能不破坏自动计时，不出现双行动。
4. `step` 下 8s 超时自动普攻；关闭战斗不留定时器（`B.pendingTimers` 清空）。
5. 10 连战无卡死、无内存泄漏（节点数回落到基线）。

**全局**
- 旧存档（`slimeSummonerSave` 存在但无新字段）加载后五个 tab 均可正常渲染与操作。

| 风险 | 处置 |
