## 二、升级带来的变化（要点）

1. **存档升级到 v2 + 安全网**：`saveVersion:2`、`abyssUnlocked`。首次载入旧档时校验字段（数字越界、重复 ID、`__proto__` 注入都会被拒），并写入一次性升级前备份 `slimeSummonerSave_v1_backup`。检测到坏档时**停止自动写入**并弹「存档保护」，原始字节保留，可用「清除损坏存档并重新开始」自救（原包的导出/导入入口已按项目要求移除，见第五节）。
2. **结算修正**：胜利全额奖励，失败只给「已击败敌人」的 25%，零击败零收益；奖励按恢复前的存活快照发放，捕捉敌人也不会漏算。
3. **深渊逐层解锁**：默认只开第 1 层，胜 N 层解锁 N+1，输入框与加减按钮都受上界约束。
4. **成长与合体**：统一成长公式 `p + (l-1)×round(p×0.5)`，`addExp` 用增量叠加并支持连续升级；合体改为主宠原地继承（保留名字/ID/经验/亲密/珍爱锁），费用 `500 + 100×最高等级 + 250×次数×(次数+1)`，带确定性预览与「状态变了要重新确认」的过期保护，副宠被珍爱锁时拒绝。
5. **战斗有预告**：敌方真实意图队列（训练/治疗/低血防御/每 3 回合 1.65× 重击），控制可取消预告，目标死亡会改锁；三场教学挑战分别练护盾、控制、净化。
6. **界面改版**：默认「陪伴」首页（今日目标 + 派遣摘要 + 亲密度里程碑），标签顺序变为 陪伴/召唤/探索/背包/成长；设置弹窗只调整主题（原包的存档导出/导入已按要求删除，见第五节）；emoji 图标换成内置 SVG 图标集；三个区域的探险场景换成不同的内置 SVG 地标；派遣不再被「陪伴空间」和小游戏暂停。
7. **诊断模式不再写存档**：`?selftest=1`、`?gallery=1`、`?battle=*`、`?fps=*` 下 `save()` 直接返回，避免自检数据覆盖玩家真实进度——这也是为什么截图脚本改成纯内存夹具。

## 四、集成时对交付包的四项修正（本次新增，非原包内容）

四项都是窄屏（390px）下肉眼可见的排版瑕疵，前三项只动 CSS/定位，第四项给气泡加了「上方放不下就翻到脚下」的兜底：

1. `.theme-btn` 从横排改为竖排（圆点在名称上方）并给名称加 `white-space:nowrap`（`史莱姆.html:429`）。原包在设置页把「星空紫 / 薰衣草」压成每行一个字。
2. 新增 `.task-row>.btn{flex:0 0 auto;white-space:nowrap}`（`史莱姆.html:437`）。原包在「战斗课堂」把「练习」按钮挤成两行。
3. 伙伴里程碑气泡（亲密度 ≥30 时出现在史莱姆头顶）改为可换行 + 自动回移：`.sys-bubble` 去掉 `white-space:nowrap`，加 `max-width:min(62vw,210px);white-space:normal;overflow-wrap:anywhere;text-align:center`；`renderSpace()` 中气泡 `classList.add('show')` 之后按 `#playground` 可视区测量，溢出时用 `margin-left` 整体平移回屏幕内（`史莱姆.html:987`、`史莱姆.html:2687-2691`）。原包在史莱姆靠近右缘时，长句气泡（如「甲：把小小的安心交给你：有你在真好。」）会被视口裁掉一截。
4. 头顶空间不足时气泡翻到脚下：新增 `.sys-bubble.below` 及箭头翻转规则（`史莱姆.html:1001-1003`，`top:100%;margin-top:4px`，箭头改到气泡上沿），`showLine()` 里 `box.top + 14 - bh < pgBox.top + edge` 时加 `below` 类（`史莱姆.html:2686`）。第 3 项只解决水平方向，史莱姆贴在场景上沿时气泡仍会冒到场景外；第 4 项兜住垂直方向。

四项都不在自检覆盖的造型 CSS 区间（`.slime{--sz:1;` 到 `.mon-badge{`）之内，`tests/review-tests.cjs` 的「原造型未改造」断言仍通过；改后浏览器自检 42/42、Node 回归 48/48 均复跑通过。

## 五、按要求移除存档导出/导入（对交付包的功能删减）

项目负责人明确要求删除交付包自带的存档导出/导入，理由是该入口实际用不上。已删内容：

- 设置弹窗整个「存档与离线」区块与四个按钮（导出当前存档、导入存档、导出升级前备份、导出浏览器原始数据），设置页现在只有主题切换和一行离线说明。
- 函数 `exportSave(kind)`、`importSaveData(raw)`、`importSave()`、`hasSaveBackup()`、`getPersistenceWarning()`，以及对应的 `exportSave`/`importSave` 事件分支、图标映射与 `.save-warning` 样式。
- 导入前备份键 `slimeSummonerSave_pre_import_backup` 不再写入。

保留（这些不是导出/导入入口）：

- 载入时的存档校验 `validSaveData()`（数字越界、重复 ID、`__proto__` 注入仍会被拒，坏档仍会停写）。
- 首次从 v1 迁移时写入的 `slimeSummonerSave_v1_backup`——界面上已没有导出口，仅作为迁移出问题时的本地回滚凭据。
- 新增「清除损坏存档并重新开始」按钮：坏档弹窗原先靠「导出原始存档 / 导入有效备份」两条出路，删掉导入导出后会变成死胡同。该按钮二次确认后 `localStorage.removeItem(SAVE_KEY)` 并重载，已在真实浏览器点验（`migration-check.js` 第 13 项）。

随之删除的验证物：`tools/out/io-check.js`（22 项导出/导入浏览器验收）及其报告与截图；`tests/review-tests.cjs` 里 4 项导入事务检查；触屏套件的夹具改用「直接写 localStorage + 重载」代替 `importSaveData`。

## 六、回退方法

`backup/史莱姆-20261027-1404-pre-slime-upgrade.html`（SHA-256 `60a7b0…`）是替换前的原始文件，改名覆盖回 `史莱姆.html` 即可回退。注意：回退后用新版存档（含 `saveVersion:2`）启动旧版，旧版会忽略不认识的字段，宠物和金币仍在；但旧版若写回，会丢掉新字段（深渊解锁进度、旅途目标等）。

## 七、仍未覆盖的部分

- 触屏验证走的是 Chrome 的触控事件管线（`Input.dispatchTouchEvent` + 390×844 `maxTouchPoints=5`，页面内 `pointerdown/pointermove/pointerup`），与真机浏览器共用同一套 pointer 事件处理，但**没有在 iOS Safari / 安卓真机上试过**；未覆盖多指捏合、长按菜单这类系统级手势。
- 触屏套件为了避免游戏自身的随机性干扰断言，做了两件事：冻结「自由活动」定时器、把伙伴先摆到固定位置再松开（不干预后续手势）。个别步骤（空白处跟手）在落点被占时会自动重试最多 3 次，日志里会打 `FOLLOW-ATTEMPT`。
- 存档导出/导入已删除，因此「存档换设备」「导入备份救档」这两条路径不再可用；坏档只剩「清除并重新开始」。
- 动画、粒子、震屏等表现只在自检的断言层面验证（普攻不震屏、暴击才有强信号），未做逐帧目视。
- 三场教学挑战的完整「正确操作通关」在 VM 回归里跑通（真实 `nextTurn`/`playerCast`），浏览器里只截了首回合界面，未逐回合点完。
