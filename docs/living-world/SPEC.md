# 史莱姆共同生活规格 · V4

目标：你和自己召唤的史莱姆，一起经营一个会留下共同回忆的家。完整统一现有内容，示例闭环是内部验收点。替代旧版并列陪伴/家园、分离库存和固定主角规则。保留中文、触屏、单文件离线及原史莱姆造型。

## 导航与生活
主导航只有家园、远行、伙伴。全局背包和设置；召唤、成长、合体在伙伴内，深渊、教学、扫荡在远行内。保留魔物照料、幼体和所有小游戏。
六个12×12家园分区保留布局。生活与布置读取同一份位置、设施和道路。伙伴只有一个地点，使用原角色绘制；移动时避开建筑，优先道路。生活首屏展示地图、伙伴和当前愿望。设施操作点击展开，生态和库存详情按需打开。
饲料槽容量99，实际到达后扣除一份；厨房加工原料，餐桌消耗料理并按关系就座；工作者照料植物并保留现有元素生态加成；小屋/温泉恢复状态；玩具区接入接球、叠叠乐；纪念角展示具体参与者与选择。建筑移动后重新寻路，不可达则暂停服务。动画不结算奖励。

## 物品
唯一Inventory，仓库、槽内和旅行容器之间转移守恒。旧bag.food→feed；旧world.stock.food→ingredient；旧feedTrough→槽内feed；其余物品分别保留。种子按品系ID记账，品系元数据不再重复保存数量。
一级厨房：ingredient 1→feed 2，60秒；ingredient 2→meal 1，60秒。保留旧配方和商店饲料。聚餐消耗料理。小食只提供有上限的偏好互动。
近家采集每300秒提供原有木材8/石材6/露水4/食材1，并提供feed 1；无基础种子时补充甜萝卜种子。最初主动短途无食物门票，体力可自然恢复。金币/食物/种子均为零仍可恢复经营。

## 伙伴与故事
宠物ID贯穿名字、成长、活动、关系和经历。故事开始绑定参与者，改名/切换查看不转移故事。真实种植、照料、制作、旅行、工作或聚餐推动阶段；只点击正文不能连读完。只有实际参与者得到记忆。重要回忆不截断，普通日志可限长。
六条区域故事、72个探索事件、八组48章、42条三段性格链、24个关系事件全部接入。固定人物成为来访者/配角，新章节不自动招募。已培养的旧固定角色及额外名额保留。每章产生可查看的关系、行为、物件或路线变化。
条件结构化且执行时校验，包括元素、性格、材料、设施和参与者；必需进度有无特定元素的路径。失败只记录实际失败。故事等待期间不占用伙伴。合体副宠历史按原ID永久归档，未完成故事在合体预览提示并确认中止，不转给主宠。
示例：召唤命名→共同种植照料→愿望→制作便当→森林同行选择→发光种子→家园花开→夜间到花边休息和共同纪念。任意元素均可完成，胆小性格有相应回应。

## 远行
六地区按发现数0/1/3/6/10/15开放，经营不要求深渊。一起出游四节点，选择与队伍保存；熟悉对应路线后委托采集，时长300/1200/3600/10800秒，默认单次、可连续，普通事件自动完成，重要剧情留给出游。队伍1–3，最多三支进行中旅程；返程释放占用，物资可稍后领取。疲劳休息、召回和续行由同一规则推进。
委托收益复用旧派遣公式，六区两区一档使用原草原/黄昏/雪原倍率。出发显示产物、特殊机会、补给和家园变化。补给可选便当或基础饲料，委托费用为max(1,ceil(duration/1200))份便当或双倍饲料；费用出发时支付，召回保留已完成收益。挑战入口承接原深渊/教学/扫荡，统一占用、库存和记录，保留战斗成长与编队规则。

## 数据与迁移
SaveV4版本4；Inventory唯一物品账本；CompanionActivity统一占用查询；SceneResident保存位置和目标；StoryInstance保存定义/参与者/阶段/选择/结果/完成；GameEvent携带发生时间、参与者、对象。规则无DOM依赖，操作先校验再一次提交，失败无扣费。
统一时钟和可保存游戏随机数；视觉随机不影响结果；离线最多12小时，回拨不倒退；同输入在线/离线相同。
V1/V2/V3读取前校验并保存原始字节备份；在副本上按旧规则结清离线一次；旧自动派遣回家并保留预设，已有家园远征及队列继续；分开迁移物品，宠物/建筑/种植/成长/幼体/已完成故事不丢失；仅保留能确定的历史，不编造参与者，不补发旧奖励；校验V4后保存再启新时钟。旧草原/黄昏/雪原记录映射晨露草甸/赤晶峡谷/霜铃雪原。
备份失败、坏档、未知版本、跨标签冲突停止写入；存储失败保留待保存内存，重试不重做结算。战斗刷新安全中断，不补发胜利奖励。

## 验收
完整闭环；原角色外观；改名/切换/合体身份；无风能力拒绝及替代；库存守恒/零资源恢复；活动互斥/位置/寻路；全部故事条件与效果；V1–V3迁移/一次结算/失败保护；真实浏览器点击触摸拖放/断网刷新/320、390、480及桌面/主题昼夜减少动态/截图；类型检查/规则集成/成长战斗回归/性能正常55FPS、压力30FPS。只测得的环境记为通过。

## 实现契约与可恢复性

| 接口 | 保存内容和约束 |
|---|---|
| `SaveV4` / `GameState` | 根版本与世界版本均为 4；保留原玩法成长字段和队伍预设 |
| `Inventory` | `items` 是仓库，`containers.trough` 是槽内，`containers[trip:ID]` 是旅行物资，`pending` 是溢出待领取；物品按用途独立 ID |
| `CompanionActivity` | 由显式战斗/游乐活动、正在进行的远行与岗位统一推导；同一 ID 最多占一个活动，已返程未领取不占用 |
| `SceneResident` | ID、所属分区、格子、目标、到达及不可达状态；两个地图模式读取相同居民与布局 |
| `StoryInstance` | 定义、绑定 ID、阶段、行为计数基线、每次选择、实际结果和完成/归档状态；阶段奖励与选择同时提交 |
| `GameEvent` / 行为记录 | 当时参与者、对象、游戏时间与实际收益；日常记录限制长度，重要回忆和纪念物保留 |
| `Host` | 原 JavaScript 玩法提供角色绘制、保存、成长和导航；规则保持 DOM 无关的 TypeScript 接口 |

`bag.food`、`feedTrough`、`world.stock`、品系 `seeds` 和旅行 `bag` 是兼容访问接口，指向同一份物品数据；V4 JSON 不重复保存这些字段。现代存档出现第二份旧库存时拒绝导入。

加工开工即记录参与者，领取时切换查看对象不会转移制作经历。发光花愿望要求绑定伙伴实际制作便当；基础饲料或其他伙伴制作均不满足。森林末节点确保出现树洞选择；邀请协助要求至少两位真实同行者，独自同行可以慢慢观察。两种选择都能完成愿望，胆小伙伴在得到支持后会主动提出尝试。

到场且道路可达的工作者才贡献生态、浇水、产出加成和共同工作经历。布置时居民继续活动，触摸手势穿过居民选中设施。聚餐按关系安排相邻的可达座位，一次扣除对应料理；抚摸、小游戏、故事和食物效果全部由规则发生，动画开关不影响结果。

原自动派遣的地图记录按 0→晨露草甸、1→赤晶峡谷、2→霜铃雪原映射，并保留可用路线及队伍选择。委托连续出发每次自动补充基础饲料，补给不足时回家停止；材料、晶币与每次行动经验分别一次结算。扫荡使用空闲队伍并留下挑战记录。

迁移前原文备份键为 `slimeSummonerSave_v3_backup`，更老版本同时保留其 v1/v2 备份。已有不同备份时另存带时间和序号的键，逐字读回核验。完整原文保留成功后才在内存副本中执行旧离线推进。新设施优先利用空位，满布局时进入收纳；不移动旧设施。任何备份、引用检查或最终写入失败都保留原存档并停止写入。

运行中保存失败时保留常驻重试入口，暂停直接操作和计时结算。战斗中已排队动作保留顺序，接球在去程、回程与漏球后均能恢复；重试成功后继续同一次活动，不跳过动作或重复奖励。跨标签冲突保持停止，重新加载后采用已保存状态。

新世界的重要回忆保留历史参与者，包括合体后的副宠 ID；普通旅行册最多 100 条、日常行为明细最多 400 条，累计行为条件仍独立保存。共同工作/旅行/聚餐按实际两位伙伴分别记录，不能借用它们各自与第三位伙伴的经历。
